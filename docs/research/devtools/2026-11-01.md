用户明确：不需要拍照/录像出文件；目标是之后用模拟器运行自定义固件（原厂2.12之上的扩展，见[平台记录](../platform/undated.md)），因此要求是“正确模拟硬件”，并尽量复用FujiMod及其他参考项目。本节是差距复核与路线，不改运行核心，没有连接实体机身。

## 结构性阻碍：当前是重放验证器，不是硬件模型

终态 `research/rec-layer-control-20261031/continuation/capture/terminal.state.json` 中共有31个 `synthetic:true` 条目，44个固件源码/输入哈希字段。多数fixture声明 `maximumCommands 1`、`reentrySupported false`、`hardwareOwnerKnown false`、`unsupportedRoutedAccess reject`，即只放行原厂2.12某一次执行轨迹。后果：

- 修改过的DAT会被 `profiles/index.json` 的整文件哈希及各fixture的源码guard拒绝。
- 即使是原厂固件，只要做出重放账本以外的操作（再次进入某模式、第二次请求），也会撞上“只支持一次”的拒绝。
- passive discovery下共1,556,245行未建模访问被静默放行（frontierView只保留1024行），未知寄存器按影子存储工作，掩盖硬件语义。

## DRAM 大小

board profile沿用FujiMod catalog的512MiB（`dram_basis: Declared catalog input`）。固件实际在core1/core3写入`3E1AE000..3E1B1xxx`、读取`3E18F000`，约994MiB处，被记为unsupported。xdevs的GFX50S II拆解显示同为X-Processor 4的PoP内存为Micron MT53E256M64D4NZ（16Gbit，即2GiB LPDDR4）。X-T4实际容量仍需实证（固件内存表或真机读取），当前512MiB很可能偏小。

## 推荐顺序

1. 基础设施：自定义DAT准入（版本/布局校验替代整文件与源码哈希）、未知访问按窗口完整计数、REC检查点、GDB接口、DRAM容量核实。
2. 以FujiMod XP5/XPP/通用IP替换fixture：gates → F_I2C及从机 → SD主机+桥+FAT卡 → 成像reset/preview/MOVDC/MOVRSZ → 场景输入。
3. 真机校准（只读优先）：ff80 cmd01/cmd02读取各GPIO端口、ADC静态值及按键/拨盘映射，替代profile中猜测的 `gpio`/`adc`。
4. 未知域（FF70xxxx、SPI2子MCU协议）需静态逆向，必要时再评估ff80 RAM读取。

每一步以“strict模式下未建模访问数下降、fixture数下降、原厂固件仍到达拍摄UI”为验收。

## SD卡、写保护、GIC与音频DMA：拍摄界面去掉“卡错误”

- **SD控制器**：两个卡槽是标准SDHCI（`FFFC4000`、`FFFC8000`，基址 `FFFC4000+槽×0x4000`；`+0x2000` 处是焊盘/驱动强度配置），时钟字就是SDHCI的 `+0x2C`。直接复用FujiMod `SdHost` + `sd_card::Card` + `card_contacts` + `fat::format`（XP5 `board/sd.rs` 的接法），两槽各一张16 GiB空FAT32卡。中断号取证于GIC：控制器首次产生中断时固件新使能的线分别是230（槽1）和237（槽2）。FujiMod自己的X-T4配置同样没有SD主机。
- **按SDHCI/SD规范放宽FujiMod模型的过严之处**（均由X-T4实跑报错定位）：ACMD13/ACMD51/CMD6的数据块不受CMD16约束，SD状态按实际总线宽度；CMD6接受标准查询/切换参数；Host Control 2只放行驱动强度位；数据完成、PIO方向、SDMA边界只要求状态使能（允许轮询）；命令进行中允许改中断使能、命令阶段结束后的参数寄存器、SD时钟启停与CMD/DAT复位；Present State补全卡检测、写保护引脚与DAT/CMD线电平，并支持16位读上半字（驱动在 `0x11b7d6c` 用它检查DAT线，读成0时放弃数据传输）。报错信息附带命令、参数与寄存器值。
- **写保护极性**：固件在 `0x011b9efc` 把Present State bit19置1判为写保护（`0x00e25130` 设置槽1保护标志），与Linux `sdhci-milbeaut` 声明的反向写保护一致；`SdHost::with_inverted_write_protect()` 只在XP4打开。此前画面中的“卡保护”即来自这里。
- **GIC缺陷**：FujiMod GICv2清挂起（ICPENDR）会无条件清掉电平触发SPI；GICv2 §4.3.8规定输入仍有效时保持挂起。驱动在注册处理函数前清IRQ230，导致“缓冲区可读”中断丢失、CMD18超时后重配时钟。已修正。
- **音频DMA**：早期合成的链式DMA输入在每个描述符块后都发IRQ211；卡可写后固件进入录像待机，WAVE处理函数 `0x0125d6b0` 把每个IRQ当作传输结束，电影状态机随后报 `ERR_SYSTEM_HALT(0x901c)` 并关闭LCDC1平面。改为只在链结束时发中断（单元测试相应改为1次）。
- **FFFAB000**：单一驱动（`0x123edf8`）写配置后 `+0=0` 等待bit0；新增 `xp4-display-clock`（声明50 µs=2700 tick锁定，身份未证），实测GPIO/ADC路径因此越过原卡点，在6.9亿条指令处出现首个向导画面。
- **结果**：9个向导帧哈希不变；向导后依次为清空的取景缓冲（全绿，`c21af92a…`）、灰场、最终拍摄界面 `7f0d1b25…`（无卡错误/卡保护，卡1图标正常，剩余41m22s，MIC电平有显示）。夹具按实跑更新。
