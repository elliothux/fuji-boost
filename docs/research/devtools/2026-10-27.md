## 2026-10-27：Go 移植与 Web 集成

**可以用 Go 实现模拟器的调度、设备、固件与工具逻辑，但纯浏览器全量移植不是普通编译切换。** FujiMod 是 Rust 核心 + C Unicorn + TS UI，浏览器另有 Emscripten/Unicorn 执行适配。Go 官方支持 js/wasm，但本机 1.26.4 和上游平台表均显示该目标无 cgo；Unicorn Go binding 依赖 `import "C"`，不能直接随标准 Go 编进浏览器。TinyGo 需单独 PoC，不能先宣称兼容。

Go 为主体的现实路径是本地 Go + cgo/Unicorn + Web UI；纯浏览器优先则先保留现有 Rust/C Wasm，经 JS/worker 接口调用，按实际需要迁移 Go 模块。前者需本地或服务器进程，后者没有完成全量 Go 移植。虚拟时间/IRQ/DMA、多核调度、跨语言回调和状态快照语义均需保留。完整比较与来源见 Go 移植评估。本轮只检查工具链目标能力和源码，没有实现或测速移植。

## 2026-10-27：本地 Rust/Wasm DevTools 实现进度

已建立 React + TanStack Router + Tailwind + Vite + shadcn/ui 工作台，Bun 管理依赖。浏览器 Worker 实际加载用户提供的 X-T4 2.12 DAT，完成四段解压、精确 SHA-256 身份识别、数据检查与 IndexedDB 保存。页面中固件加载与 CPU 执行状态分别显示。

执行层复用固定提交 `1de936e9b1ca738b04ad5132c727288ddd5eb2ae` 的 FujiMod XP4 board 和 Unicorn。新增 `crates/xp4` Rust 桥接及 Emscripten Wasm 构建，使用上游 `cold_plan` 生成 RAM 预加载布局并明确报告四处修改；不称为原厂 ROM reset。严格模式不为未知外设自动补零。

**原生与 Wasm 的实测结果一致：** 7,346 条指令，per-core `[4877, 837, 815, 817]`，寄存器完全一致，均停在 `WriteUnmapped address=0xfff4a400 size=4`。执行结果：native、Wasm。`scripts/test-xp4-wasm.ts` 用实际 DAT 执行并比较两个结果。

REA/Hopper 从真实 loader 确认 `0x4f34` 是通用写入 helper，调用者 `0x8d88` 接受 0/1 并写同一外设地址；启动路径写 1，清理引脚配置的路径写 0。推测是 I/O 全局 enable/isolation，但准确硬件语义未知，现有 GPIO / keyed-I/O 模型不能直接替代。报告与完整 Evidence：启动前沿分析。

浏览器端到端验证已完成：选择实际 DAT → 执行 100k 指令预算 → 页面显示 7,346 条实际指令、四核寄存器与同一外设停止原因。截图与核验记录：界面、验证清单。React 标题临时变更与 Rust 文件变更触发的热重载均已验证。修复了 Vite/Node 调用 Bun 构建的边界，以及构建输出触发递归编译的问题。`bun run setup`、生产构建、类型/格式/Clippy 检查和默认单元测试在当前机器通过；未做全新机器安装验证。

**目标仍未完成：** 尚未验证 X-T4 完整开机、LCD 菜单、拍摄或无线协议。当前通过的检查只证明固件解析、真实局部 CPU 执行及 Wasm/native 一致，不能当作完整 X-T4 模拟器通过。下一步继续补充有依据的 XP4 板级设备与启动流程，并保留严格失败报告。
