## 2026-10-27：自定义固件变砖与恢复

**有变砖风险，当前不能承诺 X-T4 刷坏后可自行恢复，也没有可量化概率。** 已复核 [X-T4 官方固件页](https://www.fujifilm-x.com/global/support/download/firmware/cameras/x-t4/) 与其链接的 [官方错误/恢复说明](https://fujifilm-dsc.com/en-int/manual/error_message_recovery/)：更新失败可能导致不能正常工作；部分恢复提示允许补充正确固件，其他失败要求授权维修。通用恢复说明不能证明任意 X-T4 自定义固件损坏都可恢复。

[FujiMod Recovery](https://fujimod.com/recovery/) 已有 SD 恢复交互页，但 [当前型号进度](https://fujimod.com/) 中 X-T4 2.12 的 Mods 与 SD-boot image 仍为 Not yet；不能把该页面或 X70 双启动示例当作 X-T4 兜底。正常更新入口、独立 ROM/卡启动、服务/硬件写回是不同层级，目前未取得本机后两者的闭环证据。

先做离线/模拟和有明确范围的 RAM 扩展，再研究独立恢复，最后考虑持久刷写。保存官方 DAT、模拟通过、no-op roundtrip、其他机型修复或备份 RAM 都不足以保证救砖。完整来源与条件分析见 [recovery-risk.md](../../../research/recovery-risk.md)。本轮没有刷写或恢复实机。

## 2026-10-27：Chrome 实查 FujiMod Dev Tools 与双启动源码

**补充恢复结论：最新代码已有匹配本地 DAT 的 X-T4 2.12 恢复/SD 启动配方；仍没有本研究验证过的机身启动/救砖闭环。** 本轮保留旧 checkout，只 fetch 并审阅新提交 `1de936e9b1ca738b04ad5132c727288ddd5eb2ae`。`xt4-212` recipe 的 `missing=[]`，且有 updater/DDR/加载配方，按 availability 源码满足可构建条件；同提交 X-T4 进度的 `sd-image` 与 `sd-boot` 仍为 `not-run`。两种证据不能混用。

使用 Chrome 原生窗口实际查看 Dev Tools、主页和 Recovery，并通过本地文件选择器让 Recovery 识别 `FWUP0024.DAT`。网页显示 X-T4 2.12、完整系统/绿灯镜像下载入口，文件列为 `ffinit.bin`、`ffboot.bin`、`ffdata.bin`、`FWUP0024.DAT`。文件保存到网站本地浏览器固件库；没有点击构建下载、写 SD、连接相机或刷写。主页当时提示 release index invalid，未启动网页仿真演示。

双启动在这里指内置原厂系统与 SD 装载到 RAM 的系统两条路径。先验证卡启动，可减少直接覆盖唯一可启动系统的风险；设置/校准仍使用内置存储，不是完全隔离。源码明确不覆盖内部存储被清零或打乱的情况，不能保证任何损坏都能救回。X-T4 catalog 的候选 SD 开机组合为 USB 断开、Fn1 + 后拨轮按压；Recovery 更新流程再加 DISP/BACK，均未在本机验证。

值得复用：Firmware/Corpus、XP4 CPU/外设与执行底座、Emulator UI、ff80/Workflows、模拟 USB、Recovery 卡构建。模拟 USB 当前实现显式针对 EXR2 runtime，不是 X-T4 已支持声明。完整能力矩阵、源码快照和操作边界见 最新评估；39 个选定源文件及 hashes 在同目录，旧研究基线保留。
