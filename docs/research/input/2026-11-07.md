## 2026-11-07：原厂2.12触摸面板链路静态逆向

**结论：X-T4触摸芯片挂在XP4 I2C unit2（0xfff3f000，GIC67），7位地址0x55，INT进GIC153；原始坐标空间900×600。** 模拟器里该I2C单元未建模，原厂触摸初始化每次都在地址阶段失败并放弃，所以当前只能按键。以下全部来自REC checkpoint的RAM静态反汇编和已有frontier记录，没有访问实体相机。

### 证据来源

- RAM：`.cache/xt4-rec.checkpoint`（meta factory `linked_dma_input`，firmwareSha256 `853d273b…`，1742520606 instructions）。`.cache/touch/extract-ram.py`按checkpoint chunk还原稀疏RAM，`code.bin`为前0x2400000字节，`code.elf`仅为反汇编包装。
- 反汇编：llvm-objdump 19，`--triple=armv7a`，输出在`.cache/touch/*.s`（本地，不入库）。
- frontier：合并`.cache/xt4-tests`已保存的`*state*.json`中fallback访问记录。

### 任务与状态

- TSK_TOUCHPANEL（`task.h`中0x55）的ThreadX TCB在0x6c3e4（名`touchPane`，prio4，stack 0x19979a8/0x1000）。Fuji任务包装入口0x55828共用，真实入口在TCB扩展+0xe4：**0x01215b34**。
- 任务状态结构0x1792c28：+0x8/+0xc两个event group，+0x14 IRQ句柄，+0x20保存的reg0x12值，+0x24按压计数，+0x28锁，+0x30/+0x3c两个触点槽，+0x48回调。
- 触摸ISR 0x1215380只做`event_set(state+0x8, 0x10)`；0x1215340对+0xc置0x20。数据读取在任务上下文完成。
- 驱动接口表中0x1215238固定返回 **900×600**（strh #900 / #600），与LCD像素尺寸一致，作为原始坐标空间。

### 中断

- 0x11b10ec(n)返回描述表0x15836bc的第n项（16B：irq、priority、cfg、目标核掩码）。触摸用 **#128 = GIC153，priority 0xa0，cfg3，core0**。
- 0x11b1114把irq−151映射到0..15，推断151–166为16路外部中断线，153是第2路。板模型已有先例`InputIrq{port0,pin4→155}`，按此类推153可能对应port0 pin2，**未证实**；建模时由设备直接驱动GIC153即可。
- I2C unit0/1/2的中断描述索引为0x1582c58[unit]={3,4,5}，即 **GIC65/66/67**；unit ISR 0x11a8e3c/0x11a8e28/0x11a8e14都调用公共状态机0x11a8a50(unit)。

### GPIO

- 0x1215314复位：`0x11a2cc4(0x70002,0)`后`0x11a2c80(0x70002,1)`；0x121548c调用`0x11a2c80(0x70002,0)`。即port7 pin2，推断为触摸复位/使能脚。两个helper最终都调0x11a2abc(kind, port, mask<<16|value)，kind分别为0/1，具体是方向还是输出电平未证实。

### I2C通道与API

- 0x11a95c4(ch)返回通道表0x1582c74（3B：7位地址、flag、unit）。**通道14 = {0x55, 0, unit2}**。unit2上另有0x1d等。
- 0x11a927c为纯写，0x11a937c为纯读，0x11a9480为先写后读（重复起始）。每unit软件状态在0x1788dbc+unit×32，信号量ID来自0x1582c48[unit]。
- 控制器基址 **0xfff3d000 + unit×0x1000**。寄存器布局与Fujitsu F_I2C / Linux `i2c-synquacer`逐位一致（字节寄存器，步长4）：

| 偏移 | 寄存器 | 原厂用法 |
| --- | --- | --- |
| +0x00 | BSR | ISR读：AL 0x20、LRB 0x10、TRX 0x08、FBT 0x01；忙等BB 0x80 |
| +0x04 | BCR | 0x11a8844按位写 INT/INTE/GCAA/ACK/MSS/SCC/BEIE/BER（bit0–7）；ISR读BER 0x80、MSS 0x10 |
| +0x08 | CCR | EN 0x20、HSM 0x40、CS低5位（12或24） |
| +0x10 | DAR | 地址字节`addr<<1|rw`与数据 |
| +0x14 | CSR | 写8或2 |
| +0x18 | FSR | 写3 |
| +0x1c | BC2R | 2位 |

- 公共ISR 0x11a8a50的状态机：BER或AL→错误；MSS=0→错误；TRX=1时LRB=1→NACK错误，否则剩余发送字节写DAR并以INT=0重写BCR继续；发送完且有读段→DAR=addr<<1|1、BCR置SCC重复起始；读段FBT=1为地址阶段，之后每次INT读DAR，最后一字节前清ACK；结束时清MSS产生STOP。与`i2c-synquacer`驱动行为相同。

### frontier佐证

unit2（0xfff3f000，core0）同一序列重复60次：写+0x18=3、+0x14=8，读+0x00两次，**写+0x10=0xaa（0x55<<1）**，读+0x04得fallback 0x52，写+0x04=0x40，写+0x08=0x0c。因控制器未建模，地址阶段之后没有GIC67，事务超时后放弃。unit1另有boot代码和core3的174次访问（含一次+0x10=0x6c，即地址0x36），与触摸无关。

### 芯片协议（地址0x55）

- 写寄存器：0x12153a8发送`[reg, data…]`（≤30B）。读寄存器：0x1215a98先写`[reg]`再重复起始读。
- 电源表0x13d828c由0x1215410使用：开启写reg2=0x01再reg1=0x01；关闭写reg1=0x00再reg2=0x00。
- 自检0x1215ae8：写reg0xF6=[0x12]，再读reg0x12一字节，存到state+0x20；之后不一致会触发复位（0x1215314+0x1215948）。
- 数据读取（0x1215d88、0x1216734）：
  - 读reg **0x10** 2B → b[0]=触点数，b[1]=状态（`b[1]&0x18`为错误）；
  - 读reg **0x11** 7B两次 → b[2..8]、b[9..15]；读失败时b[0]=0xAA；
  - 32B缓冲与上次memcmp（0x1281b98），变化才复制。
- 触点解码0x1215e14：每条7B记录 `state, x_lo, x_hi, y_lo, y_hi, ?, ?`。state低4位为手指ID（1或2），**bit7为按下**（0x12157c0以ldrsb取符号判断）。count==1时按ID决定落在哪个槽。
- 0x12157c0在锁内按槽维护阶段：1新按下（分配计数）、2持续、3抬起、0空闲；x/y存入+0x32/+0x34与+0x3e/+0x40。

### 仍未知

- reg0x12的含义（固件版本/ID），记录第6、7字节，0x1215948、0x1215a08/0x1215a1c的完整作用。
- INT为电平还是边沿（描述cfg3按GIC推断为边沿），以及释放事件后芯片是否再拉一次INT。
- 坐标是否随翻转屏方向变换（消费者侧）；芯片具体型号。

## 2026-11-07：按真硬件建模并接到模拟器

未访问实体相机。模型在 `references/fujimod/crates/emulator-xp4-io/src/touch_i2c.rs`，经 `patches/fujimod-devtools.patch` 进入板图；设备放在图的最后，缺省时旧 checkpoint 的图不变。

### 模型

- F_I2C unit2 窗口 `0xfff3f000`，GIC67；7 位地址 0x55 ACK，其余 NACK。字节完成约 1215 tick（400 kHz），报告周期 540,000 tick（10 ms）。
- 读 0x10 锁存报告并放下 INT；0x11 流出两条 7B 记录。按下在两次报告之间结束时仍先报一次 down 再报 up。
- 0x12 为扫描计数：每次地址阶段写成 `now / report_ticks`。原厂看门狗写 0xF6=`[0x12]` 再读 0x12，值不变就复位芯片。
- GIC153 按边沿：未读走的报告在下一拍先拉低再拉高，避免一条未处理的电平把面板静音。

宿主入口 `Session::set_touch`。原厂会话默认不加这块设备；`Xp4Session::discover_linked_dma_input_touch` 在实测 GPIO/ADC 之上 opt-in，checkpoint identity 带 `/touch-panel`。自定义映像会话始终安装。

### 自定义固件

`firmware/src/hal/touch.rs` 轮询 ISPENDR bit 153（不开 153，避免帧循环清掉使能位）。`input.touch` 已进 fuji-xt4 profile。网页 LCD 在映像模式下把指针映射到 900×600。`crates/xp4/tests/custom.rs` 的 `pocket_touch` 与浏览器点 +1 均已通过。

### 原厂 2.12 实测输入冷启动

`stock_touch`（ignored）：约 715–720M 指令后驱动给面板上电（reg1/2=1），unit2 不再出现在 frontier。注入 (450,300) 后任务槽 0 为 id=1、down、坐标 450×300、stage=1；松开后 down 清掉、stage=3。自检与配置序列与静态结论一致（含 0x30 的 26 字节表、0xF4/0xF5、0xF6/0x12）。

带触摸从冷启动走完 measured REC 向导会在向导 9 之后停在 imaging-sensor 的 `reconfiguring active sensor command`。同一路径不装面板可以通过。多出来的 F_I2C deadline 改变了传感器 DMA 命令窗口，不是面板协议错误。REC 画面上的 TP_TOUCH_ON/OFF（0xb000/0xb001）因此仍未观察到。
