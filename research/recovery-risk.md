# X-T4 自定义固件变砖与恢复风险

核对日期：2026-10-27（Asia/Shanghai）。本轮为公开资料复核，无相机操作。

**同日后续源码与 Chrome 补充：** 新提交 `1de936e9b1ca738b04ad5132c727288ddd5eb2ae` 已有 X-T4 2.12 recovery recipe，按源码可用性条件可构建；Chrome 现场加载同哈希 DAT 后也显示完整系统和绿灯镜像入口。但 X-T4 `sd-image` / `sd-boot` 的公开进度仍为 `not-run`，没有本研究的构建或机身恢复验证。应把下文“未验证恢复”理解为缺少闭环，而非不存在候选实现。详见 最新评估。

## 结论

写入自定义固件有导致无法启动、功能异常或需要硬件维修的风险，当前没有证据可以量化概率。现阶段没有本研究已验证的 X-T4 自定义固件刷写/恢复闭环，不能承诺刷坏后重刷官方 DAT 即可恢复。只有更新文件的备份也不是完整存储/校准备份，更不是独立恢复入口。

## 当前官方与社区证据

1. [X-T4 官方固件页](https://www.fujifilm-x.com/global/support/download/firmware/cameras/x-t4/) 的 Precaution 明确提示，更新失败可能导致相机不能正常工作；要求充满电并在覆盖固件期间不要关机或操作。页面链接至下述错误处理页。
2. [官方错误与恢复说明](https://fujifilm-dsc.com/en-int/manual/error_message_recovery/) 区分文件/型号错误、恢复阶段找不到更新包，以及无法正常完成更新。某些恢复提示要求卡上放置对应固件后重新开机，另有失败情况要求授权维修机构处理。**有这份通用说明不等于 X-T4 在任意自定义固件故障后都能进入恢复。** 页面的 flash 附件故障重试说明也不能移用为机身固件强制断电指导。
3. [FujiMod 仓库](https://github.com/justjake/fujimod) 的项目简介警告先验证双启动再考虑刷写。此警告不是 X-T4 已支持双启动的证明。
4. [FujiMod Recovery](https://fujimod.com/recovery/) 公开了从原厂 DAT 生成 SD 恢复文件、卡启动后刷回原厂的交互页面。仅看到这个页面不证明其支持本型号。此次未上传/选择本地固件，也未生成或执行恢复镜像。
5. [FujiMod 型号进度](https://fujimod.com/) 中 X-T4 2.12 的 Mods 和 SD-boot image 仍为 Not yet，后者列出 Image built / Booted on a camera 尚待完成；机身测试为 Needs an owner。首页当前实际推广的机身 SD 双启动是 X70。故当前所查公开状态不支持把 X70 恢复步骤用于 X-T4。
6. [fffw 项目](https://github.com/tiredboffin/fffw) 搜索返回将 ffre 恢复工具标为 unpublished、abandoned、put on hold；它不是可直接拿来恢复 X-T4 的发布工具。

本次没有找到 X-T4 特定的、可复现的变砖后独立启动和写回流程。搜索范围是上列官方页面、FujiMod 当前公开进度/恢复页及 fffw；不据此断言私人研究或所有其他资料中都不存在。

## 按故障边界看恢复可能性

以下为工程条件判断，不是 X-T4 已实测恢复教程。

| 情况 | 可能恢复方式 | 限制 |
|---|---|---|
| 更新包被校验拒绝且尚未写入 | 保持原固件，改用对应的官方文件 | 拒绝包不一定已经变砖；必须确定是否已发生擦写 |
| RAM 中的实验代码崩溃 | 结束临时运行或在合适时机重新上电，回到未改动启动镜像 | 前提是未改非易失存储/校准/控制器；RAM 代码仍可能调用持久写入，不是绝对安全 |
| 主应用错误但更新器/独立入口仍可运行 | 通过实际可用入口重新安装官方固件 | 型号/版本约束、损坏范围、入口是否依赖坏掉主固件都需要验证 |
| 正常更新器无法运行，但独立 ROM/卡启动仍有效 | 机型专用恢复镜像启动，再写回匹配镜像 | 当前未验证 X-T4 对应方式，不能指定 ffboot.bin/ffsys.bin 等为通用解法 |
| 启动存储、持久配置或校准受损，且无软件入口 | 厂商服务；必要时板级调试/外部编程或更换部件 | 需确认芯片接口、锁定/验证状态与完整正确备份；不可承诺编程器必能救回 |

正常 DISP/BACK 更新入口依赖相机能执行相应代码。没有证据表明它是独立于主固件、永远可用的 ROM 恢复机制。出厂设置重置和取出电池通常也不能重写已损坏的固件；不要在正在擦写时拔电池。

## 风险来源与开发顺序

自定义代码即使被更新器接受，仍可能因版本地址/加载图错误、多核与任务状态错误、压缩/布局/完整性更新错误，或持久数据写坏而无法启动。不修改 bootloader 只能减少部分故障范围，不能证明正常升级入口仍然可用。当前 bit-exact no-op roundtrip 只证明无改动重建，不证明修改包可运行或可恢复。

建议顺序：离线逆向与局部模拟 → 已确认执行范围的 RAM 扩展 → 验证 X-T4 独立启动/恢复（如研究取得该能力）→ 再评估常驻 Flash 补丁。先把恢复流程在未变砖的同版本机身上验证到明确程度：确认何种故障仍可进入、镜像匹配规则、恢复写入范围与校准保留。不要为了验证而故意破坏启动链。

如要做持久刷写，不能以“手里有官方 DAT”“有 RAM dump”“模拟器能跑”“其他机型救回过”代替恢复证明。在恢复链路未确认时，用唯一或承担日常工作的机身实验，应按可能需要付费维修甚至更换主板的后果决策；维修结果和费用尚无本机证据。

没有进行刷写、设备连接、恢复文件生成或硬件维修验证。
